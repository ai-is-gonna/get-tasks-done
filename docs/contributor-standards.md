# Contributor Standards

Keep contributions focused, reviewable, and aligned with the current workflow.

## Code And Docs

- Prefer small PRs with one concern.
- Update public docs only when behavior changes for users.
- Keep examples current with the GitHub task issue workflow.
- Avoid adding internal issue IDs or inherited project history to docs.

## Testing

- Add regression tests for bug fixes.
- Add focused behavior tests for new features.
- Prefer structured assertions over broad text matching unless the text itself
  is the product.

## AI-Agent Contributions

AI-assisted contributions are welcome when the final diff is reviewed like
normal engineering work. Do not commit prompts, local scratch notes, or generated
planning artifacts unless they are intentional product documentation.
